# 문제

전체 악성은 인증서 존재가 3%인데 Low 악성은 \*\*88.9%\*\*입니다. 우리가 처음부터 경고했던 \*\*“서명된 악성코드도 존재한다”\*\*가 실제 오류로 나타난 겁니다.





원인 1

서명된 악성 파일이 정상적인 정적 특성을 많이 가짐



원인 2

PE Warning이 전혀 없음



원인 3

Import/Section/Overlay 구조도 일반 악성과 다름



추가 확인 필요

18건이 실제 18개 파일인지,

9개 파일이 중복된 것인지 SHA-256 확인 필요



추가 확인 필요

Histogram / ByteEntropy가 이 9개 패턴을 왜 정상 쪽으로 밀었는지 확인



진행중 문제 확인

===

데이터셋 쪽 특징: Validation 내부에 같은 SHA-256 파일이 중복 포함되어 있었음
우리가 잘못한 부분: 처음 Validation을 60,000행 그대로 평가해서 동일 SHA 파일이 2번씩 들어간 사실을 먼저 확인하지 못함

그래서 오류가 두번 중복 되어 있었음

중복 제거후 고유악성9건에 대한 분석 진행 



고유 Low 악성 = 9개



공통 패턴:

\- 대부분 인증서 존재

\- PE Warning 없음

\- Core 정상 유사

\- ByteEntropy 정상 유사

\- Histogram은 악성 유사



→ 정상적인 PE처럼 위장된 정적 특성을 가진 악성군일 가능성



고유 Low 악성 9개 분석
---

→ 하나의 동일 원인으로 놓친 것이 아님



공통적으로는:

CORE 제거 시 가장 크게 점수 상승



하지만:

Histogram / ByteEntropy도 모델 상호작용에 관여



따라서 특정 Feature 그룹을 제거하는 해결책은 부적절
